# Portfolio CMS setup

The public site remains a static Vite/GitHub Pages application. Supabase provides authentication, database storage, and media storage for editable content.

## 1. Create a Supabase project

Create a project in the Supabase dashboard. Keep the database password somewhere secure; it is not used by the website frontend.

## 2. Run the schema

Open **SQL Editor** in Supabase and run `supabase/schema.sql` from this repository.

This creates:
- `admins`
- `about_profile`
- `interest_pages`
- `content_blocks`
- a public `portfolio-media` storage bucket
- Row Level Security policies

## 3. Create the administrator account

In Supabase Dashboard, go to **Authentication → Users** and create a user with your preferred administrator email and password.

Use a long, unique password generated by a password manager. Do not put the password in GitHub, Vite, a .env file, or the database.

Copy the new user's UUID and run this in SQL Editor:

```sql
insert into public.admins (user_id)
values ('PASTE-THE-AUTH-USER-UUID-HERE');
```

Only authenticated users whose UUID appears in `public.admins` can write portfolio content.

## 4. Add the browser-safe Supabase settings to GitHub

In the Supabase project settings, copy:
- Project URL
- Publishable key (or anon key if your project still shows the legacy naming)

In GitHub repository:
**Settings → Secrets and variables → Actions → Variables**

Create:
- `VITE_SUPABASE_URL`
- `VITE_SUPABASE_PUBLISHABLE_KEY`

These are browser-facing values. Never add a Supabase `service_role` or secret key to this site.

## 5. Administrator login

After deployment, visit:

`https://wenchuanzhu.com/admin`

Sign in with the Supabase Authentication email/password created in step 3.

The admin UI supports:
- About heading/body/photo
- New Interest pages
- Teaching as an Interest page
- Text blocks
- Image uploads
- Video uploads
- External image/video URLs
- Draft/published status
- Basic ordering

## 6. Password changes

Change/reset the administrator password through Supabase Authentication. The website never stores or knows the raw password.

## 7. Security model

Public visitors:
- can only read published About/Interest content
- can read media in the public portfolio bucket

Administrator:
- must authenticate with Supabase Auth
- must also be listed in `public.admins`
- can create/update/delete CMS content and upload/delete media

The frontend never receives a service-role credential.
